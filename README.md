تحويل نظام Calling System من Google Apps Script إلى تطبيق ويب احترافي يعمل على Supabase و Vercel

## 🚀 البدء السريع

### 1. إعداد Supabase

1. اذهب إلى [supabase.com](https://supabase.com) وأنشئ مشروع جديد
2. انسخ `database/schema.sql` بالكامل
3. اذهب إلى SQL Editor في Supabase وأضفه
4. قم بتشغيل الـ SQL لإنشاء الجداول والدوال

### 2. تكوين المشروع

انسخ `.env.example` إلى `.env.local`:

```bash
cp .env.example .env.local
```

ثم حدّث الملف:

```env
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

### 3. الاختبار المحلي

```bash
# لا حاجة لخادم محلي - افتح index.html مباشرة
open index.html

# أو استخدم Python
python -m http.server 8000
# ثم افتح http://localhost:8000
```

### 4. النشر على Vercel

**خيار 1: عبر CLI**
```bash
npm install -g vercel
vercel login
vercel --prod
```

**خيار 2: عبر GitHub**
1. أدفع المشروع إلى GitHub
2. اذهب إلى [vercel.com](https://vercel.com)
3. اختر "Import Project"
4. أضف متغيرات البيئة
5. انشر!

## 👥 الأدوار والصلاحيات

### 1️⃣ الموظفات (Employee)

**الواجهة:**
- تاب **كل الطلبات**: عرض جميع الطلبات المسندة
- تاب **بدون حالة** (🔴): الطلبات التي لم تُحدد حالة العميل فيها
- تاب **بانتظار الشحن** (🟠): الطلبات الجاهزة للشحن

**الميزات:**
- عرض تفاصيل الطلبة
- تحديث حالة العميل
- عد محاولات الاتصال
- نسخ البيانات

### 2️⃣ مسؤولو المتاجر (Store)

**الواجهة:**
- تابات حسب حالة الطلبات:
  - رد و يستلم
  - استبدال
  - مرتجع
  - مؤجل

**الميزات:**
- تحديث فوري لحالة الطلبات
- رؤية الطلبات المعلقة
- متابعة الطلبات بدون حالة

### 3️⃣ المديرين (Admin)

**الواجهات:**

#### 📊 الإحصائيات
- KPIs رئيسية (إجمالي، مسلم، غير مسلم، نسب)
- إحصائيات الموظفين بالرسوم البيانية
- إحصائيات المتاجر
- حالات العملاء
- حالات الشحنات

#### 🏪 المتاجر
- أداء كل متجر
- الطلبات المعلقة بالمتجر
- نسب التسليم

#### 📋 كل الطلبات
- قائمة شاملة لجميع الطلبات
- تحرير وحذف الطلبات
- إضافة ملاحظات

#### 🔍 البحث
- البحث عن طلبات بالكود أو رقم العميل
- البحث في الطلبات المؤرشفة
- تعديل البيانات القديمة

#### 📱 المتابعة
- الطلبات التي تحتاج متابعة
- تحديث حالة المتابعة
- تنبيهات الطلبات المعلقة

## 🛠️ تكوين قاعدة البيانات

### الجداول الرئيسية

#### `orders` - الطلبات
```sql
order_code TEXT UNIQUE NOT NULL      -- كود الطلب
customer_phone TEXT NOT NULL         -- رقم العميل
employee_name TEXT                   -- اسم الموظفة
store TEXT                           -- اسم المتجر
client_status TEXT                   -- حالة العميل
shipment_status TEXT                 -- حالة الشحنة
delivered TEXT                       -- (محسوبة) تم التسليم
```

#### `deliveries` - التسليمات
```sql
order_code TEXT UNIQUE NOT NULL      -- كود الطلب المسلم
customer_phone TEXT NOT NULL         -- رقم العميل
delivery_date TIMESTAMP              -- تاريخ التسليم
```

#### `follow_up_orders` - الطلبات المعلقة
```sql
order_code TEXT NOT NULL             -- كود الطلب
follow_up_status TEXT                -- حالة المتابعة (pending, completed, failed)
follow_up_date TIMESTAMP             -- تاريخ المتابعة
```

### الدوال المهمة

#### `recalculate_calculated_columns()`
تعيد حساب جميع الأعمدة المحسوبة:
- `delivered`: هل تم التسليم
- `delivery_filter`: نوع التسليم
- `dashboard_filter`: هل تظهر في الداشبورد

تشغيل يدوي:
```sql
SELECT recalculate_calculated_columns();
```

## 🔐 الأمان

### RLS (Row Level Security)
- عام يمكن قراءة الطلبات المرئية
- المصادقين فقط يمكنهم التحديث
- المديرين فقط يمكنهم الحذف والأرشفة

### المصادقة
- Supabase Auth مع البريد وكلمة المرور
- جلسات آمنة مشفرة
- تحقق من الدور قبل السماح بالعمليات

## 📈 الأداء

### التحسينات
- فهارس قاعدة البيانات على جميع حقول البحث الرئيسية
- حسابات على مستوى قاعدة البيانات (أسرع من JavaScript)
- Views مُحسّنة للإحصائيات
- تحديث آلي للبيانات كل 30 ثانية

### حدود الاستخدام المحلية
- تطبيق ويب ثابت (Static)
- لا توجد حدود على عدد المستخدمين المتزامنين
- PostgreSQL يدعم ملايين الصفوف

## 🚨 استكشاف الأخطاء

### المشكلة: "Cannot connect to database"
- تحقق من `SUPABASE_URL` و `SUPABASE_ANON_KEY`
- تأكد من إنشاء الجداول (`schema.sql`)
- جرّب تحديث الصفحة

### المشكلة: "Permission denied"
- تحقق من أن المستخدم له الدور الصحيح
- تأكد من تفعيل RLS policies
- حاول تسجيل الخروج وإعادة الدخول

### المشكلة: "No data showing"
- جرّب `SELECT recalculate_calculated_columns();`
- تأكد من وجود بيانات في الجدول
- فحص `dashboard_filter != 'Ignore'`
