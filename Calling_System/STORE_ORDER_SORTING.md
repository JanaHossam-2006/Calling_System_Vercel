# تثبيت ترتيب الطلبات لمسؤول المتجر

## المطلوب
الطلبات في واجهة مسؤول المتجر يجب أن تُرتب حسب التاريخ (من الأقدم للأحدث)، ولكن عند تحديث حالة الطلبية إلى "تم" أو "لم يتم"، يجب أن تبقى الطلبية في نفس موضعها ولا تنزل لأسفل القائمة.

## المشكلة السابقة
كانت الطلبات تُرتب حسب التاريخ، ولكن عند تحديث حالة الطلبية من مسؤول المتجر، كان عمود "التاريخ" يتحدث بالوقت الحالي، مما يجعل الطلبية تنزل لأسفل القائمة.

## الحل المطبق

### 1. في Backend (Code.gs)

#### دالة `handleStoreActionBackend`

**التعديل الرئيسي:** إزالة تحديث عمود "التاريخ" عند تحديث حالة التبليغ

**قبل:**
```javascript
// تحديث التاريخ أيضاً لتوثيق وقت الرد
const dateCol = headers.indexOf('التاريخ');
if (dateCol !== -1) {
  const now = new Date();
  const dateStr = `${pad(now.getDate())}/${pad(now.getMonth() + 1)}/${now.getFullYear()} ...`;
  sheet.getRange(rowIndex, dateCol + 1).setValue(dateStr);
}
```

**بعد:**
```javascript
// لا نحدث عمود "التاريخ" هنا حتى لا يتغير ترتيب الطلبات
// عمود "التاريخ" يحتفظ بتاريخ آخر تحديث من الموظفة (عند الاتصال بالعميل)
```

### 2. في Frontend (JavaScript.html)

الترتيب يبقى حسب التاريخ:
```javascript
if (state.userRole === 'store') {
    filteredOrders.sort((a, b) => parseLibyaDate(a['التاريخ']) - parseLibyaDate(b['التاريخ']));
}
```

## كيف يعمل الحل؟

1. **الموظفة تتصل بالعميل** → يتحدث عمود "التاريخ" بوقت المكالمة
2. **الموظفة تحدد الحالة "رد و يستلم"** → التاريخ يبقى كما هو
3. **الطلبية تظهر لمسؤول المتجر** → مرتبة حسب تاريخ المكالمة
4. **مسؤول المتجر يحدد "تم" أو "لم يتم"** → التاريخ **لا يتغير**
5. **الطلبية تبقى في نفس موضعها** → الترتيب ثابت ✅

## النتيجة

✅ **الترتيب حسب التاريخ**: من الأقدم للأحدث  
✅ **الطلبات لا تتحرك**: عند تحديث "تم" أو "لم يتم"  
✅ **سهولة المتابعة**: مسؤول المتجر يعرف مكان كل طلبية  
✅ **منطقي**: الترتيب حسب وقت اتصال الموظفة بالعميل

## ملاحظات

- عمود "التاريخ" يتحدث فقط من الموظفة عند الاتصال بالعميل
- مسؤول المتجر لا يغير التاريخ، فقط يحدث "تبليغ المسؤول" و "ملاحظه المسؤول"
- الترتيب يعكس أولوية الطلبات (الأقدم أولاً)

5. الطلبات ستبقى في نفس موضعها عند تحديث الحالة ✅
